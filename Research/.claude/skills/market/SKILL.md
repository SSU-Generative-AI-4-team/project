# 시장·경쟁사 조사

`Research/CLAUDE.md`의 출처·교차검증 규칙을 따른다. 그 규칙이 이 절차보다 우선한다.

## 1단계: 조사 질문 확정

조사를 시작하기 전에 **답하려는 질문 한 문장**과 **이 조사로 내릴 결정**을 사용자와 합의한다. 둘 다 불분명하면 조사하지 말고 먼저 묻는다.

- 나쁜 질문: "경쟁사 조사해줘"
- 좋은 질문: "우리가 ○○ 기능을 넣어야 할지 정하려는데, 경쟁 서비스 3곳이 그걸 어떻게 처리하는가?"

## 2단계: 비교 대상 선정

1. 후보를 넓게 수집한다 (WebSearch). 직접 경쟁, 간접 경쟁, 인접 영역을 모두 본다.
2. 3~6개로 좁힌다. **선정 기준을 명시한다** — 왜 이것들을 골랐고 무엇을 뺐는지.
3. 대상이 많거나 각각 깊이 봐야 하면 `source-collector` 서브에이전트를 대상별로 병렬 호출한다.

## 3단계: 비교 축 정의

**대상을 조사하기 전에 축을 먼저 정한다.** 순서가 반대면 눈에 띄는 것만 비교하게 된다.

- 축은 1단계의 조사 질문에서 도출한다.
- 각 축에 가중치(상/중/하)를 매긴다. 전부 중요하면 아무것도 중요하지 않다.
- 축은 4~7개가 적당하다.

## 4단계: 자료 수집

각 대상 × 각 축을 채운다.

- **1차 자료를 우선한다**: 공식 웹사이트, 가격 페이지, 문서, 공식 발표. 리뷰 기사는 2차 자료다.
- 가격·수치는 **접근 날짜를 반드시 기록**한다. 가격은 자주 바뀐다.
- 확인되지 않은 칸은 추측으로 채우지 말고 `[미확인]`으로 둔다.
- 중요한 수치는 독립된 출처 2곳에서 확인한다. 1곳뿐이면 `[단일 출처]` 표시.

## 5단계: 비교표 작성

`templates/comparison-matrix.md`를 복사해 채운다.

- 표의 셀에는 **사실**만 적는다. "좋음/나쁨" 같은 판단은 축별 판단 근거 섹션에 쓴다.
- 판단에는 근거 출처를 붙인다.

## 6단계: 인사이트 도출

비교표를 나열하는 것으로 끝내지 않는다. 다음을 답한다.

1. **패턴**: 모든 경쟁사가 공통으로 하는 것은? (→ 기본 기대치)
2. **공백**: 아무도 안 하는 것은? (→ 기회 또는 함정 — 왜 아무도 안 하는지 먼저 생각한다)
3. **시사점**: 1단계의 결정에 대해 이 조사가 말하는 것은?

## 7단계: 저장 (필수)

1. 비교표를 `notes/YYYY-MM-DD-주제슬러그-comparison.md`로 저장
2. `templates/research-note.md` 포맷으로 조사 노트를 `notes/YYYY-MM-DD-주제슬러그.md`에 저장
3. 사용한 모든 출처를 `sources/source-log.md`에 추가 (없으면 새로 만든다)
4. 팀에 공유할 확정본이면 `outputs/`로 옮기고 사용자에게 알린다

## 체크리스트

- [ ] 조사 질문과 내릴 결정이 문서 맨 위에 적혀 있다
- [ ] 비교 대상 선정 기준이 적혀 있다
- [ ] 모든 수치에 출처와 접근 날짜가 있다
- [ ] 미확인 항목이 `[미확인]`으로 남아 있다 (빈칸을 채워 넣지 않았다)
- [ ] 인사이트가 표 요약이 아니라 결정에 대한 답이다
- [ ] `sources/source-log.md`가 갱신됐다
