# 기술·문헌 조사

`Research/CLAUDE.md`의 규칙을 따른다. 문헌 조사에서 인용 정확도는 타협 대상이 아니다.

## 1단계: 조사 질문과 범위

- 답하려는 질문 한 문장
- **범위를 명시한다**: 기간(예: 2023년 이후), 언어, 분야, 제외 조건
- 범위를 정하지 않으면 끝없이 넓어지고, 나중에 무엇을 안 봤는지 설명할 수 없다

## 2단계: 검색어 설계

1. 핵심 개념을 2~4개로 분해한다
2. 각 개념의 **동의어·유사어**를 나열한다 (분야마다 다른 용어를 쓴다)
3. 조합해 검색어를 만든다
4. **사용한 검색어를 기록한다** — 재현 가능해야 한다

## 3단계: 자료 수집

- 자료가 많으면 `source-collector` 서브에이전트를 주제별로 병렬 호출한다
- 수집 단계에서는 거르지 말고 모은다. 선별은 다음 단계에서.

### 자료 등급

| 등급 | 종류 |
|---|---|
| 1차 | 원 논문, 공식 스펙·표준 문서, 공식 문서, 직접 측정 데이터 |
| 2차 | 리뷰 논문, 교과서, 검증된 기술 매체 |
| 참고 | 블로그, 포럼, 슬라이드 — 단서로만 쓰고 근거로 쓰지 않는다 |

**2차 자료에서 본 내용은 1차 원문을 찾아 확인한다.** 찾지 못하면 `[2차 인용: 경유 출처]`로 명시한다.

## 4단계: 선별

범위 기준으로 거른다. **제외한 것과 제외 이유를 기록한다.** 이게 있어야 나중에 조사 신뢰도를 판단할 수 있다.

## 5단계: 요약

자료별로:

- **핵심 주장** 1~2줄
- **근거·방법**: 어떻게 그 결론에 도달했는가
- **한계**: 저자가 밝힌 한계 + 내가 본 한계
- **우리 질문과의 관련성**: 1단계 질문에 이 자료가 무엇을 답하는가

> 초록만 읽고 요약하지 않는다. 초록과 본문 결론이 다른 경우가 흔하다. 본문을 못 봤으면 `[초록만 확인]`으로 표시한다.

## 6단계: 종합과 갭 분석

자료를 나열하는 것이 문헌 조사가 아니다.

1. **합의**: 여러 자료가 일치하는 지점
2. **이견**: 자료끼리 충돌하는 지점 — 양쪽을 다 적고 왜 다른지(방법·조건·시점 차이) 설명한다
3. **갭**: 아무도 다루지 않은 부분 — 우리 조사 질문이 여기에 걸리는지 확인
4. **결론**: 1단계 질문에 대한 현재까지의 답, 그리고 확신 수준

## 7단계: 인용 표기

일관된 형식으로 정리한다. 기본형:

```
저자, "제목", 출처/학회/저널, 발행연도. URL (접근: YYYY-MM-DD)
```

- DOI가 있으면 DOI를 함께 적는다
- 모든 인용은 실제로 읽은 자료여야 한다

## 8단계: 저장 (필수)

1. `templates/research-note.md` 포맷으로 `notes/YYYY-MM-DD-주제슬러그.md`에 저장
2. 검색어, 범위, 제외 기준을 노트에 함께 남긴다 (재현성)
3. 모든 출처를 `sources/source-log.md`에 추가
4. 확정본은 `outputs/`로

## 체크리스트

- [ ] 조사 범위와 검색어가 기록돼 있다
- [ ] 제외한 자료와 이유가 기록돼 있다
- [ ] 2차 인용에 `[2차 인용]` 표시가 있다
- [ ] 초록만 본 자료에 `[초록만 확인]` 표시가 있다
- [ ] 자료 간 이견이 은폐되지 않고 드러나 있다
- [ ] 갭 분석이 있다 (요약 나열로 끝나지 않았다)
