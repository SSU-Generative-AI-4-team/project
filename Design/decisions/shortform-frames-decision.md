# 숏폼 광고 프레임 시안 설계 근거

- 작성자: Claude Code로 작성 (작성자 이름 확인 필요)
- 날짜: 2026-11-17
- 관련 파일: `frontend/shortform_frames.html`

## 배경

광고로 돌릴 숏폼 영상(9:16, 15~20초)을 만들기 전에 장면 순서와 첫 3초 훅을 프레임으로 먼저 맞춘다. 12주차 강의자료(훅 모양 다섯, 쇼츠 대본 = 첫 2초 훅 + 장면 4개)를 따랐다.

## 검토한 대안

| 소재 | 훅 | 비고 |
| --- | --- | --- |
| 보내지 않은 메시지 · POV · 궁궐 앞 해치 | 질문 · 장면 | 말로 끄는 훅이라 자막이 길어짐. 2차 후보 |
| 실제 화면 데모 · 먹 갈기 | 장면 · 소리 | 앱 화면 녹화가 필요하거나 재방문용. 다음에 |
| 숫자 훅 | 숫자 | 근거 숫자(테스터 데이터)가 없어 제외 |

## 최종 결정과 근거

훅 방식이 서로 다른 3개로 1차 시안을 만든다. 같은 끝 장면을 두고 첫 3초만 비교하기 위해서다.

- A 해치 먹방 ASMR: 소리 + 패턴 깨기
- B 메모장 vs 해칫: 반전(비교) + 장면
- C 해치의 한마디: 캐릭터 대사 + 되감기 · 루프

`brand_1013.md`는 자극적인 말을 쓰지 않으므로 훅은 말 대신 소리 · 움직임 · 의외의 장면으로 만든다. 자막은 금지어(소각 · 힐링 · 치유 등)를 피하고 "원문은 남지 않아요"로 쓴다. 사람 얼굴 · 지어낸 숫자 · 후기는 넣지 않는다. 자막은 릴스 · 쇼츠 UI가 가리지 않는 영역 안에 둔다.

## v2 수정 (2026-11-17) — Meta 광고 적합성 검토 반영

v1은 브랜드 영상에 가까워 광고 소재로는 약하다고 판단해 고쳤다.

| v1 문제 | v2 |
| --- | --- |
| 검은 화면 · 정지 장면으로 시작 | 첫 프레임부터 움직임(타이핑 · 씹기 · 스크롤) |
| 무엇인지 모름 | 모든 영상에 실제 서비스 화면 한 번(랜딩 체험 칸 문구 그대로) |
| 18~20초 | 12~13초 |
| 소리에 기댐(A) | 자막을 크게, A는 릴스 전용 |
| "사전 신청"은 부담이 큼 | "지금 해치에게 건네 보기" → 랜딩 체험 |

우선순위: D 실제 화면 녹화(신규) → B 메모장 vs 해칫 → C 해치의 한마디 → A(릴스 전용). 성과는 같은 몸통 · 다른 첫 3초로 소액 테스트해 3초 재생률 · 링크 클릭 · GA 체험으로 비교한다.

## 새 방향: 자막을 먹는 해치 (2026-11-24)

- 관련 파일: `frontend/shortform_caption_eater.html`(영상 원본), `frontend/shortform_video/haechit_caption_eater.mp4`(14.5초, 1080×1920)
- 배경: 앱 화면이 단조로워 화면 녹화형(A~D)만으로는 눈길을 끌기 어렵다. 앱 화면 대신 "해치가 말을 먹는다"는 설정을 주인공으로 삼았다.
- 결정: 자막 카드가 뜨면 해치가 옆에서 나와 세 입에 먹는다. 감각 훅은 한입 자국 + 화면 흔들림 + 한지 조각 + 씹는 소리. "바삭" 글자는 뺐다.
- 자막 순서: 불편(털어놓고는 싶은데 기록이 남는 건 싫을 때 → 메모장에 쓰면 계속 남아 있잖아요) → 해결(해칫에 적으면 해치가 먹어 없애요) → 좋은 점(적은 말은 어디에도 저장되지 않아요) → 행동. 서비스를 모르는 사람이 봐도 무엇인지 알 수 있게 하기 위해서다.
- 해치 대사는 광고 영상에서 해요체로 쓴다("잘 먹었어요. 읽지는 않았어요."). `brand_1013.md`의 하오체 규칙과 다르므로 팀 확인이 필요하다 `[확인 필요]`.
- `[확인 필요]` 효과음(씹기 · 연필 · 보내기)은 Freesound 커뮤니티 소리다. 광고 집행 전 라이선스를 확인한다. "어디에도 저장되지 않아요"는 실제 서비스가 원문을 저장하지 않아야 쓸 수 있다.
